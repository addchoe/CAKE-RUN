# 데모 / 수동 검증

## 90초 시연

1. `simDebug` 실행. 크림·토핑·장식을 눌러 케이크가 바뀌는지 확인.
2. `부드럽게` 시나리오로 출발. 가상 속도·시간·거리가 갱신되고 케이크가 가볍게 움직이는지 확인.
3. `가상 급제동`과 `가상 급회전`을 누릅니다. 기울기와 보존 점수 변화, 충분한 손상 후 균열/토핑 손실을 확인.
4. `데모 조기 도착`을 눌러 등급·점수·이벤트 횟수를 확인.
5. 새 배송을 시작해 누적값이 초기화되는지 확인. 거친 주행과 부드러운 주행의 결과를 비교.

## 경계 조건

| 동작 | 기대 결과 |
|---|---|
| 배송 중 홈 화면으로 이동 | 앱은 시뮬레이션을 멈춤 |
| 프로세스가 유지된 채 복귀 | 배송이 이어지고 백그라운드 시간은 누적되지 않음 |
| 프로세스 종료 후 다시 실행 | 저장된 진행분의 결과 표시 |
| 결과 화면에서 오래 대기 | 점수·이벤트 횟수 변화 없음 |
| 새 배송 | 이벤트·거리·손상 초기화, 꾸미기 유지 |
| 60초 대기 | 자동 결과 이동 |
| 작은 가로 화면 | 우측 제어 영역 세로 스크롤 가능 |

## Pleos에서 추가 확인

- `pleosDebug` 상단에 motion이 SIMULATION으로 표시되어야 함.
- Virtual Console 브레이크 변경 → 상단 SDK ON/OFF 상태 변화. 케이크 물리 입력에 섞이지 않아야 함.
- 준비 화면에서 공식 예제 목적지 요청 → 연결 전이면 대기 안내, 연결 후라면 완료/오류 콜백 상태 표시.
- 성공 시 잔여 거리/시간 표시. 내비 도착 콜백과 60초 자동 결과가 중복 도착해도 추가 점수 변화 없음.
- 일반 Android에서 `pleosDebug` 실행 시 SDK 연결 실패/대기 상태와 함께 시뮬레이션이 계속되는지 확인.
- 앱 전환/재진입 후 중복 구독이나 종료된 화면 갱신이 없는지 실제 SDK 환경에서 확인.

이 문서는 실행 절차입니다. 실제로 완료한 검증과 미실행 항목은 `VALIDATION.md`를 보세요. 현재 앱의 게임 임계값과 점수는 실차 승차감 또는 안전 운전의 검증된 측정법이 아닙니다.
